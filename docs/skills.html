Trick 2: The 22 skills

Tools get students hired; judgment gets them promoted.

The move. Answer “why study CS when AI writes code?” with a list, not a speech: twenty-two measurable outcomes for assessing computation. AI now writes code cheaply. Someone still must define correct, verify generated claims, review work they did not write, secure the system, and price cost against quality. We train the reviewers, not the reviewed.

The five questions (each outcome starts “Given X, the student will…” and is graded by artifact, not essay):

Is it right? — specs a second team can test; test suites that catch seeded defects; verifying generated stats and citations; reviewing alien code; proofs and tractability.

What does it cost? — benchmark AI against non-AI baselines (20+ runs, effect size); split workflows across LLM / retrieval / logic and defend the split; MVP scope with a priced do-nothing option.

Can it be trusted? — threat models; adversarial testing (prompt injection, leakage); provenance and license audits; fault diagnosis; eval beyond accuracy (calibration, fairness, drift); reproduction.

Does it scale? — up (complexity, then measure), out (load-test at 10× users), down (fit a fixed CPU/memory budget, report quality lost).

Does it fit the world? — stakeholder negotiation; experiment design with controls and ablations; learn the next tool from vendor docs alone.

The punchline. Departments that merely use AI cannot repair its defects. The department that studies the defects must teach them — to the whole college. And industry's “durable skills” (critical thinking, communication, adaptability…) are already in this set, each tested against evidence.

Cost. The list exists (memo, Appendices A and C, undergrad + grad). Coverage today: 4 outcomes solid, 7 outright gaps, rest partial.

Combines with: 1 — redose installs these outcomes into running courses; 5 — go broad picks the six that need no prerequisites; 8 — teach past the bubble is why this set holds value after the crash.
